# Quaerens Professional Case Builder Framework™ v1.0

Status: Permanent platform architecture standard
Framework: B
Owner: The Quaerens Platform™

## 1. Purpose

The Quaerens Professional Case Builder Framework™ is the internal, evidence-first framework used for guided support, professional assessments and managed consumer dispute services.

It is separate from the free Complaint Pack Framework™. The Complaint Pack Framework enables consumers to prepare their own browser-first DIY complaint packs; the Professional Case Builder enables authorised professionals to organise evidence, assess matters and produce managed-service case documentation.

The framework defines one reusable professional case-building system. It is not a separate assessment application for each service and must not evolve into duplicated category-specific systems.

## 2. Platform position

The Quaerens Platform contains four separate but connected frameworks. Each has one primary responsibility.

### Framework A — Complaint Pack Framework™

- free DIY;
- consumer-controlled;
- browser-first;
- produces professional complaint packs for consumer use.

### Framework B — Professional Case Builder Framework™

- guided and professional;
- collects and organises evidence;
- supports professional assessment;
- produces assessment reports and case files.

### Framework C — Quaerens Intake Gateway™

- qualifies Guided Support Requests;
- applies business rules;
- routes and assigns Prepared Cases.

### Framework D — Operations CRM™

- delivers operational services;
- manages people, tasks, communications, pipeline and status;
- provides workspace-controlled operational delivery.

These frameworks may exchange controlled information, but none should absorb the responsibility of another.

## 3. Core principle

Do not build another assessment system for every service.

Build and maintain one professional case-building framework. Each service is a configured route through that shared framework.

A new service must reuse the existing intake, evidence, chronology, financial, reporting and integration capabilities. Category configuration may adapt professional content but must not duplicate the underlying system.

## 4. Shared framework capabilities

Every Professional Case Builder must inherit the following capabilities.

### 4.1 Client intake structure

A consistent structure records the client and case information required for professional work. Service-specific questions may extend that structure without replacing its shared identity, consent and case-context foundations.

### 4.2 Evidence collection

The shared evidence process must:

- identify required and recommended evidence;
- record evidence received and reviewed;
- associate evidence with relevant facts and findings;
- preserve provenance and document references;
- support controlled document storage;
- avoid asking for the same evidence repeatedly.

### 4.3 Chronology

The chronology provides an ordered, evidence-linked history of material events. It must support clear dates, descriptions, categories, source references and professional review.

### 4.4 Financial impact

The financial structure records claimed, evidenced, estimated and otherwise relevant financial exposure. It must distinguish figures from conclusions and preserve the basis for every amount.

### 4.5 Document generation

The shared document-generation capability transforms structured professional work into consistent case documents. It must preserve the Quaerens report hierarchy, presentation standard and auditability.

### 4.6 Assessment report structure

Every route inherits the common professional report structure defined in this document. Category-specific sections may be inserted only where the service genuinely requires them.

### 4.7 Evidence scoring

Evidence scoring communicates readiness, coverage and gaps. It must be explainable and must not misrepresent an assessment score as a guarantee of outcome.

### 4.8 Missing evidence tracking

The framework records missing, unavailable and not-applicable evidence distinctly. Outstanding evidence must remain visible to the professional workflow and report process.

### 4.9 Internal notes

Internal notes support professional reasoning and operational context. They must remain separate from client-facing documents unless deliberately promoted into an approved output.

### 4.10 Client communications

The framework supports consistent case-related communications, requests for information, explanations and next-step messages while preserving the operational CRM as the system responsible for communication activity.

### 4.11 Audit trail

Material changes, reviews, findings, evidence decisions and generated outputs must be attributable and time-aware. The audit trail supports accountability without exposing internal material improperly.

### 4.12 CRM integration

The framework receives the minimum authorised case context required from Operations CRM and returns controlled professional outputs and relevant structured status information. Integration must use documented boundaries rather than duplicating CRM behaviour.

### 4.13 Document storage

Generated and received documents must use controlled storage with appropriate access, retention and case linkage. Storage references must remain traceable to the relevant operational case.

### 4.14 Reporting

The shared reporting structure supports consistent service delivery, quality review and operational insight across configured routes.

## 5. Category configuration boundary

Each service may customise only what is genuinely category-specific:

- questions;
- evidence requirements;
- assessment criteria;
- technical findings;
- industry terminology;
- report sections;
- recommendations.

Configuration must not silently alter the shared framework. A category-specific requirement that would change shared workflow or infrastructure must first be evaluated as a versioned framework improvement.

## 6. Framework outputs

The Professional Case Builder Framework should produce, as applicable:

1. **Professional Assessment Report** — the formal professional evaluation of the case, evidence, findings and recommended next steps.
2. **Evidence File** — the organised evidence record, including references, coverage, gaps and provenance.
3. **Client Summary** — a clear client-facing explanation of the case position and next steps.
4. **Complaint Preparation File** — the structured material required to prepare or support a complaint or dispute process.
5. **Referral Pack** — a controlled professional handoff package where an external specialist, partner or alternative route is required.

Outputs may be combined within a case-file package where appropriate, but their purpose and audience must remain clear.

## 7. Professional report standard

Every professional report should follow the Quaerens professional standard and contain, where applicable:

1. **Executive Summary** — a concise account of the matter, evidence position, principal findings and recommended direction.
2. **Client Information** — the verified client and case identifiers necessary to understand the report.
3. **Background** — relevant context, service history and the reason for assessment.
4. **Chronology** — an ordered account of material events linked to supporting evidence.
5. **Technical Findings** — category-specific professional observations, analysis and limitations.
6. **Evidence Review** — evidence considered, relevance, strength, conflicts, gaps and outstanding requirements.
7. **Financial Exposure** — evidenced or estimated financial impact with a transparent basis.
8. **Impact Assessment** — the practical, financial and other material effects supported by the available information.
9. **Recommendations** — proportionate, evidence-based options that distinguish professional guidance from guarantees.
10. **Next Steps** — clear actions, responsibilities, dependencies and priorities.

The report must read as a coherent professional assessment, not as a sequence of exported form answers.

## 8. CRM relationship

The Professional Case Builder does not replace Operations CRM. It feeds operational workflows with professional evidence documents and controlled case information.

### Operations CRM manages

- people;
- tasks;
- communication;
- pipeline;
- status.

### The Professional Case Builder creates

- professional evidence documents;
- structured assessment findings;
- evidence and chronology outputs;
- professional case files and referral material.

The CRM remains the operational system of record. The Case Builder remains the professional document and assessment system. Neither should reproduce the other's interface or responsibility.

## 10. Document quality standard

The output must feel like a professional consultancy report.

It must not resemble:

- a questionnaire export;
- a form response;
- an unstructured collection of notes;
- a generic template with case data inserted without professional organisation.

The finished work should make the client feel:

> My case has been professionally organised.

Quality depends on clear hierarchy, evidence-linked reasoning, precise language, transparent limitations, coherent recommendations and presentation suitable for professional review.

## 11. Evidence-first principles

- Findings must be traceable to evidence or clearly identified professional reasoning.
- Missing information must be visible rather than silently assumed.
- Conflicting evidence must be recorded and addressed.
- Scores and indicators must be explainable.
- Recommendations must reflect the available evidence and stated limitations.
- Generated wording must never claim certainty that the evidence does not support.
- Client-facing outputs and internal professional notes must remain intentionally separated.

## 12. Integration and responsibility boundaries

The framework must remain separate from:

- the consumer-controlled Complaint Pack Framework;
- Intake Gateway qualification and routing;
- Operations CRM task, communication, pipeline and status management;
- category-specific public website presentation.

Integration should occur through controlled contracts:

1. Operations CRM supplies authorised case context and access.
2. The Professional Case Builder collects and structures professional assessment material.
3. The framework produces approved evidence documents and findings.
4. Outputs are associated with the operational case through controlled integration.
5. Operations CRM continues the service workflow.

## 13. Security and governance

- Access must follow the authorised operational case and role model.
- Professional notes and restricted material must not be exposed as public outputs.
- Evidence and documents must have traceable ownership and access controls.
- Sensitive information must be collected only when necessary for the professional service.
- Generated documents must identify their version and case association.
- Category configuration must be reviewed before release.
- Framework changes must be explicit, versioned and regression-tested across existing routes.
- A configured route must not bypass the CRM, storage or audit controls defined for professional work.

## 14. Framework acceptance criteria

A Professional Case Builder conforms to Framework v1.0 only when:

- it uses the shared professional case-building system;
- it is implemented as a configured service route rather than a standalone assessment system;
- it inherits the shared capabilities in section 4;
- its custom behaviour remains within the category configuration boundary;
- its outputs conform to the professional report and document quality standards;
- evidence, missing evidence, chronology and financial impact remain traceable;
- CRM and Case Builder responsibilities remain distinct;
- applicable outputs can be associated with the operational case;
- internal notes and client-facing materials remain appropriately separated;
- the route is tested without damaging existing configured services.

## 15. Versioning

This document establishes:

**Quaerens Professional Case Builder Framework™ v1.0**

The framework version evolves independently from individual configured service routes.

Future changes must strengthen the shared framework rather than create separate systems. Shared improvements must:

1. state the architectural need;
2. identify all affected routes;
3. preserve framework boundaries;
4. include regression requirements;
5. increment the framework version when behaviour or contracts materially change;
6. be documented before category implementations depend on them.

Category-specific changes must record their own configuration version and must not silently change Framework v1.0.

## 16. Final statement

The Quaerens Professional Case Builder Framework™ creates consistent, evidence-first professional case documentation across all managed consumer support services.

Individual services are configured routes through one professional system.
